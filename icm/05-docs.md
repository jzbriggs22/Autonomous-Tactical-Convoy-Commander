# 05 – Docs

## Purpose
Produce the documentation, changelog entry, PR description, and handoff notes needed to ship or merge the work.

## Inputs (load only these)
- This file
- The final approved implementation + review notes
- The original requirements and design (for context only if needed)
- coding-standards.md or any docs-style notes if present

## Process
1. Write or update user-facing / developer-facing documentation.
2. Draft a clear changelog / release note entry.
3. Write a complete PR description (summary, motivation, changes, test plan, screenshots if relevant).
4. Note any migration steps, feature flags, or rollout considerations.
5. List remaining follow-up work or known limitations.

## Outputs
- Updated docs
- `icm/artifacts/CHANGELOG-entry.md` or equivalent
- `icm/artifacts/PR-description.md`
- Optional handoff notes

## Done When
A human can open a PR or ship the change with confidence using only the artifacts produced in this stage.

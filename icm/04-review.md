# 04 – Review

## Purpose
Critically review the implementation for correctness, quality, tests, security, performance, and adherence to design + standards.

## Inputs (load only these)
- This file
- The latest `[feature]-impl-notes.md` + the code under review
- The approved `[feature]-design.md` (for checking fidelity)
- coding-standards.md
- tech-stack.md (relevant parts)

## Process
1. Check fidelity to the approved design.
2. Review for correctness, edge cases, and error handling.
3. Assess test coverage and suggest missing tests.
4. Check security, performance, and maintainability issues.
5. Verify coding standards are followed.
6. List concrete, prioritized findings (must-fix / should-fix / nice-to-have).
7. Suggest a short test plan if none exists.

## Outputs
- `icm/artifacts/[feature]-review.md`
- Updated or new test suggestions
- Clear list of required changes before docs/ship

## Done When
A human has a clear, actionable review and can decide whether to send work back to implement or move forward.
